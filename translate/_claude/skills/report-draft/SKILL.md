# 보고서 초안 작성 절차

## 입력
| 입력값 | 필요한 유형 | 예 |
|---|---|---|
| type | 전체 | `weekly`, `monthly`, `project`, `research` |
| period | 전체 | `2026-W45`, `2026-10`, `2026. 1.~10.`, `2021~2025년 (전망 2030년)` |
| topic | `project`, `research` | `CRM 개편`, `전기차 시장 성장 추이` |
| author | 전체 | `docs/report-defaults.md`에서 가져옴 |

- `weekly`와 `monthly`는 보고서 ID에서 기간을 가져온다.
- `project`와 `research`는 기간이 보고서 ID와 별개이므로 반드시 받아야 한다.
- `author`와 `department`는 `docs/report-defaults.md`에서 읽는다. 비어 있으면 사용자에게 묻는다.
- 빠진 입력값은 시작하기 전에 한 번의 질문으로 모두 묻는다.

## 언어
이 절차로 `workspace/`에 만드는 모든 파일은 전부 한국어로 쓴다. `CLAUDE.md`의 언어 정책을 참고한다.

## 버전 관리
모든 초안 버전을 보관한다. 수정본은 새 파일로 저장하고 기존 버전은 절대 바꾸지 않는다. `.claude/rules/file-naming.md`의 초안 버전 관리를 참고한다.

## 작업 목록 관리
작업 내내 `workspace/<report-id>/todo.md`를 최신 상태로 유지한다 (규칙은 `CLAUDE.md`, 형식은 `.claude/rules/file-naming.md`).
- 1단계에서 보고 정보 블록과 함께 만들고, 1~11단계를 `대기`로 둔다 (1단계는 `완료`).
- 각 단계 직전에 `진행 중`으로 바꾼다. 끝나면 `완료`, `건너뜀`, `중단` 중 하나로 바꾸고 짧은 비고를 적는다 (예: `웹 검색으로 수집`, `데이터 파일 없음`).
- 9단계의 수정 라운드가 시작될 때마다 행을 추가한다.
- 결과 파일이 생기기 전에는 절대 `완료`로 표시하지 않는다.

## 단계
1. **준비.** `.claude/rules/file-naming.md`에 따라 보고서 ID를 정하고 `workspace/<report-id>/`를 만든다. 폴더에 이미 `draft_v*.md` 파일이 있으면 멈추고, 처음부터 다시 쓰는 대신 최신 버전을 수정할지 사용자에게 묻는다. 그다음 보고 정보 블록을 넣어 `todo.md`를 만든다.
2. **템플릿 확인.** `templates/<type>.md`와 `docs/template-headings.md`의 해당 섹션이 있는지 확인한다. 없으면 멈추고 사용자에게 알린다.
3. **내부 자료 수집.** `researcher` 에이전트를 실행한다 → `notes.md`.
4. **웹 자료 수집.** researcher가 `관련 자료 없음`으로 답했거나 사용자가 웹 조사를 요청했으면, 사용자에게 묻지 않고 바로 `web-researcher` 에이전트를 실행한다 → `raw_web.md`, `notes.md`. 그렇지 않으면 이 단계를 `건너뜀`으로 표시한다.
5. **자료 확인.** `notes.md`에서 출처가 있는 항목이 하나 이상인 내용 섹션을 센다. 절반이 안 되면 멈춘다: 이 단계를 `중단`으로 표시하고, 비어 있는 섹션을 나열하고, `inputs/`에 파일을 추가하거나 주제를 좁혀 달라고 사용자에게 요청한다. 초안은 쓰지 않는다.
6. **분석.** `inputs/data/`에 해당 기간 파일이 있으면 `data-analyst` 에이전트를 실행한다 → `analysis.md`, `calc.md`. 없으면 이 단계를 `건너뜀`으로 표시한다.
7. **초안 작성.** `report-writer` 에이전트를 실행한다 → `draft_v1.md`(원문)와 `revisions.md`.
8. **검수.** `draft_v1.md`에 `reviewer` 에이전트를 실행한다 → `review_v1.md`.
9. **수정.** 최신 검수 결과가 `결과: 수정 필요`인 동안 최대 2회 반복한다.
   - `review_v<N>.md`로 `report-writer` 실행 → `draft_v<N+1>.md` (작업 파일 수정 포함)
   - `draft_v<N+1>.md`에 `reviewer` 실행 → `review_v<N+1>.md`

   검수 결과가 `결과: 자료 부족`이면 수정을 멈추고 10단계로 간다.
10. **보고.** 사용자에게 한국어로 보고한다.
    - 보고서 3줄 요약
    - 남아 있는 모든 `[확인 필요]` 항목
    - 해결되지 않은 검수 항목 (있는 경우)
    - `revisions.md`의 버전 목록과 최신 초안 경로
    - 웹 자료 사용 여부와 `raw_web.md`의 출처 목록
    - `todo.md`에서 `완료`나 `건너뜀`이 아닌 단계
11. **내보내기 제안.** 사용자에게 묻는다: "최신 초안(draft_v<N>.md)을 .docx로 내보낼까요? PDF도 필요하시면 말씀해 주세요." 승인하면 `report-export` 스킬을 실행한다. 승인 없이 내보내지 않으며, 사용자가 거절하면 이 단계를 `건너뜀`으로 표시한다.

## 이후 수정 요청
사용자가 기존 보고서의 수정을 요청하면, 요청을 `todo.md`에 새 행으로 추가하고, `report-writer`로 최신 초안에서 다음 버전을 만든 뒤, `reviewer` 실행과 내보내기를 제안한다.
